Detailed Description

Header file for BSD-like socket API implementation.

Version
1.0.0
Date
2025-11-07

Thread-safe BSD socket-like API for W5500. Key Features:

  • Thread-safe operation via w5500_spi_mutex
  • Blocking and non-blocking I/O modes
  • TCP, UDP, IPRAW, MACRAW protocol support

Receive data from TCP socket.

Parameters
snSocket number
bufDestination buffer
lenMaximum number of bytes to read
Returns
Number of bytes read (>0), 0 if no data available (non-blocking mode), or negative error code on failure (SOCKERR_*, SOCK_BUSY when bounded wait elapsed).

Reads up to len bytes from the socket RX buffer. If no data is currently available, this function waits only for a short, bounded slice to avoid stalling the caller. After the slice expires, it returns SOCK_BUSY so upper layers can yield and retry. This prevents long idle connections from starving the scheduler and the HealthTask.

int32_t recvfrom ( uint8_t sn,
uint8_t * buf,
uint16_t len,
uint8_t * addr,
uint16_t * port )

Receive datagram from UDP socket.

Receives a UDP datagram with source address and port. In blocking mode, waits for data if RX buffer empty. In non-blocking mode, returns SOCK_BUSY if no data.

Supports fragmented packet reception:

  • PACK_FIRST: First call for a new packet
  • PACK_REMAINED: More data remains in current packet
  • PACK_COMPLETED: All packet data received
Parameters
snSocket number
bufPointer to receive buffer
lenMaximum number of bytes to receive
addrPointer to buffer for source IP address (4 bytes, output)
portPointer to buffer for source port number (output)
Returns
Number of bytes received, SOCK_BUSY, or negative error code
Note
Socket must be in SOCK_UDP, SOCK_IPRAW, or SOCK_MACRAW state
For UDP: includes 8-byte header (IP[4] + port[2] + length[2])
For IPRAW: includes 6-byte header (IP[4] + length[2])
For MACRAW: includes 2-byte header (length[2])
Use SO_PACKINFO to check packet completion status

Receive datagram from UDP socket.

Parameters
snSocket number
bufDestination buffer
lenMaximum bytes to receive
addrOUT: source IPv4 address (4 bytes)
portOUT: source UDP port
Returns
Number of bytes read (>0), 0 if no data available (non-blocking mode), or negative error code on failure (SOCKERR_*, SOCK_BUSY when bounded wait elapsed).

Waits briefly for a datagram, then returns SOCK_BUSY so the caller can yield and retry. Prevents long stalls when no UDP data is pending (e.g., idle SNMP). This implementation reads and consumes the 8-byte UDP header first, then the payload. If len is smaller than the payload, the remainder is read into a small throwaway buffer to advance the RX pointer, and then Sn_CR_RECV is issued once to commit consumption.

Receive datagram from a UDP socket (cooperative, bounded wait)

Reads one complete UDP datagram (header + payload) from the W5500 socket. Properly flushes the chip RX pointer with Sn_CR_RECV once the datagram is fully consumed, preventing stale header bytes from contaminating the next read. Non-blocking and bounded for cooperative multitasking.

Send datagram over UDP socket.

Sends a UDP datagram to the specified destination. In blocking mode, waits for TX buffer space if needed. In non-blocking mode, returns SOCK_BUSY if buffer full.

bufPointer to data buffer
lenNumber of bytes to send (limited by TX buffer size)

Returns
Number of bytes sent, or negative error code
Note

Parameters
snSocket number
bufPointer to data buffer
lenNumber of bytes to send
addrDestination IP address (4 bytes)
portDestination port number
Returns
Number of bytes sent, or negative error code

Sends a single UDP datagram. The W5500 requires the full datagram to fit into the socket's TX buffer in one shot; this implementation waits for TX free space only for a short, bounded slice. If sufficient space does not become available quickly, the function returns SOCK_BUSY so the caller can yield and retry on a later tick. No datagram fragmentation is attempted.
