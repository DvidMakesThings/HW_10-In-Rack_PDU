Detailed Description

Button input handling with debouncing and selection window management.

Version
1.0.1
Date
2025-11-08

This module implements a FreeRTOS task for handling physical button inputs on the PDU. It provides debounced button reading, selection window management with visual feedback, and power state control through button combinations.

Key Features:

  • Polls PLUS, MINUS, SET, and PWR button GPIOs at configurable intervals
  • Software debouncing with configurable timing thresholds
  • Distinction between short and long press events for SET and PWR buttons
  • Selection window with timeout and LED blinking feedback
  • Event queue for inter-task communication
  • Power management integration for standby mode control

Button Behavior:

  • PLUS: Move selection right (wraps around), only when window is active
  • MINUS: Move selection left (wraps around), only when window is active
  • SET (short): Toggle selected relay output, opens window if closed
  • SET (long): Clear error/warning logs and fault LED
  • PWR (long): Enter standby mode from normal operation
  • PWR (short): Exit standby mode when in standby

The selection window provides visual feedback via blinking LEDs and automatically closes after a configurable timeout period. The task operates without interrupts, using polling to maintain predictable real-time behavior.

Enumeration Type Documentation

◆ btn_event_kind_t

enum btn_event_kind_t

Button scanning period in milliseconds.

Defines how frequently the task polls button GPIO states. Lower values provide faster response but increase CPU usage. Typical range: 5-20ms.

Selection LED blink period in milliseconds.

Controls the on/off cycle time for the selection indicator LED during the active selection window. Must be long enough to be visible to users.

Selection window timeout in milliseconds.

Duration for which the selection window remains open after the last button interaction. After timeout, LEDs turn off and window closes automatically.

Storage task readiness timeout in milliseconds.

Maximum time to wait for StorageTask initialization during bring-up sequence. ButtonTask initialization fails if storage is not ready within this period.

Button event types published to q_btn.

  • Edge events: debounced PLUS/MINUS press and release transitions.
  • Press events: SET short/long press determined by duration thresholds.
  • Events are generated by ButtonTask and consumed by subscribers via the queue.

bool Button_IsReady ( void )

Query button task readiness status.

Provides a thread-safe method to check whether ButtonTask has completed initialization successfully. Used for deterministic boot sequencing to ensure proper task dependency ordering.

Returns
true if ButtonTask_Init(true) completed successfully and task is running.
false if ButtonTask_Init() was not called, called with enable=false, or initialization failed.
Note
This function is safe to call from any task context.

◆ ButtonTask_Init()

BaseType_t ButtonTask_Init ( bool enable)

Initialize and start the button handling task.

Creates the ButtonTask FreeRTOS task, initializes button GPIOs, sets up the event queue, and configures the LED blink timer. Implements deterministic initialization with storage readiness gate.

Initialization sequence:

  1. Initializes button GPIO pins with pull-ups
  2. Waits for StorageTask readiness (with timeout)
  3. Initializes power manager
  4. Creates button event queue (32 events deep)
  5. Creates and starts LED blink timer
  6. Spawns ButtonTask with configured priority
Parameters
enableSet true to initialize and start task, false to skip initialization deterministically without side effects.
Returns
pdPASS on successful initialization or when skipped (enable=false).
pdFAIL if initialization fails (timeout, queue creation, task creation).
Note
This function blocks until StorageTask becomes ready or timeout occurs.
Logs error codes to error logger on failure.

See buttontask.h for detailed documentation.

Global queue for button event distribution.

FreeRTOS queue handle used by ButtonTask to publish button events. Other tasks subscribe to this queue to receive notifications. The queue is created during ButtonTask_Init() and remains valid throughout runtime.
